# ADR-0010: PWA — manifest + service worker dengan fallback offline

- **Status**: Diterima
- **Tanggal**: 2026-10-10

## Konteks

Situs portofolio dipakai berulang oleh pemilik dan pengunjung, tetapi setiap kunjungan selalu bergantung pada jaringan. Service worker `public/sw.js` sudah ada namun **hanya** menangani Web Push (ADR-0009), tanpa manifest, ikon, atau strategi cache, sehingga situs tidak dapat dipasang sebagai aplikasi maupun dibuka saat offline. Next.js App Router menyediakan konvensi metadata (`app/manifest.ts`, `app/icon.svg`, `app/apple-icon.png`) yang memudahkan penambahan PWA tanpa pustaka tambahan.

## Keputusan

Tambahkan dukungan PWA:

- **Manifest** via `app/manifest.ts` (`display: standalone`, `start_url: /`, warna tema, ikon 192/512 + maskable).
- **Ikon** dibuat dengan skrip `npm run icons` (`scripts/generate-icons.ts`, memakai `sharp`) dan di-commit sebagai PNG statis (`public/icons/*`, `app/apple-icon.png`); favicon `app/icon.svg`.
- **Service worker** `public/sw.js` diperluas: precache `/offline` + ikon + manifest; navigasi memakai strategi **network-first** dengan fallback halaman `/offline`; aset statis (`/_next/static`, ikon, media) memakai **cache-first** dengan revalidasi latar; request `/api/**` dan lintas-origin **tidak** di-cache. Cache diberi versi (`CACHE_VERSION`) dan dibersihkan saat `activate`; handler `push`/`notificationclick` lama dipertahankan.
- Registrasi service worker lewat komponen `ServiceWorkerRegister` di root layout, **hanya di produksi**; tombol "Instal aplikasi" lewat `beforeinstallprompt` (`InstallPrompt`).

## Alasan

- PWA meningkatkan pengalaman (terpasang, splash, offline fallback) tanpa layanan pihak ketiga.
- Ikon PNG statis di-commit agar build Docker/EasyPanel deterministik; `sharp` hanya dipakai sebagai devDependency untuk generasi ikon.
- Data dashboard tetap diambil server-side; offline hanya menyajikan app-shell dan halaman `/offline`, menghindari penyajian angka basi.

## Konsekuensi

- **Positif**: situs dapat dipasang di perangkat; pengalaman lebih cepat; graceful saat tanpa jaringan.
- **Negatif**: service worker menambah kompleksitas lifecycle (versi cache, cleanup); perlu naikkan `CACHE_VERSION` saat mengubah strategi.
- **Lain-lain**: registrasi hanya di produksi agar tidak mengganggu HMR Next.js saat dev; HTML ber-autentikasi (hub) tidak di-cache untuk menghindari kebocoran/keusangan.

## Alternatif yang dipertimbangkan

- **Tanpa service worker, hanya manifest** — tidak memberi offline fallback; pengalaman PWA terbatas. Ditolak.
- **Cache offline penuh (termasuk data API stats/trends)** — berisiko menyajikan data basi tanpa label "stale" dan menambah kerumitan invalidation. Ditolak untuk saat ini.
- **Pustaka PWA (mis. `next-pwa`)** — menambah dependensi dan kurang fleksibel; konvensi Next + SW manual sudah cukup. Ditolak.
